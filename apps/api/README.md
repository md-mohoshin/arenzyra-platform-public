## Description

[Nest](https://github.com/nestjs/nest) framework TypeScript starter repository.

## Project setup

```bash
$ npm install
```

## Media background removal (sponsor logos)

- Set `MEDIA_AI_URL=http://localhost:5055` (see `.env.example`).
- Run the FastAPI service in `apps/media-ai-service` with `uvicorn main:app --host 0.0.0.0 --port 5055`.
- Sponsor uploads will call the service for background removal, then Sharp will resize/convert to WEBP. If the service is offline, uploads fall back to the regular Sharp path and log `[MediaAI] unavailable, skipping background removal`.

## Legacy PCOB compatibility

Canonical automatic ingest is the launcher `ob.js` -> API observer path. The `/pcob` surface remains only as a legacy compatibility boundary for old explicit `PCOB` matches and adapter-bound ingest.

- `POST /pcob/telemetry` accepts adapter ingest JSON guarded by `x-pcob-secret` (`PCOB_SECRET`).
- `/pcob/feed/start`, `/pcob/bind`, and producer socket `pcob:bind` are legacy-only controls for old explicit `PCOB` matches.
- `POST /org/:orgId/operator/matches/:matchId/pcob-link` and `.../pcob-unlink` are also legacy-only; they are disabled for `API` and `MANUAL` matches.
- legacy producer tooling is disabled by default and now requires explicit opt-in such as `ALLOW_LEGACY_SHADOW_API=1` or `ALLOW_LEGACY_PCOB_INGEST=1`.
- New automatic matches should use `API` only; no new setup should depend on `PCOB`, `SHADOW`, or simulator-style producer flows.

## Match slots (PUBG slot-based games)

- `GET /org/:orgId/matches/:matchId/slots` and `GET /me/matches/:matchId/slots` list active slot assignments.
- `POST /org/:orgId/matches/:matchId/slots` and `POST /me/matches/:matchId/slots` set a slot with `{ slotNumber, teamId }`. Valid only when the adapter/game declares `usesSlots=true`; enforces slot range and tournament membership.
- `DELETE /org/:orgId/matches/:matchId/slots/:slotNumber` and `DELETE /me/matches/:matchId/slots/:slotNumber` clear a slot.

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash
$ npm install -g @nestjs/mau
$ mau deploy
```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.
